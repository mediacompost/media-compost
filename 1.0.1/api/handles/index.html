    Items and tag set¶

    Every object here is a live handle: it holds a library and a primary key, re-reads when the library changes underneath it, and raises ObjectDeleted rather than answering with stale data. Assigning to a property is the edit.

    handles ¶

    The live objects a script works with.

    Each wraps one row and writes through. Nothing here holds a session in a signature: the library owns that, and every mutator goes through Library._do, which is where the autocommit-or-batch rule lives.

    The one distinction worth reading twice is on an item's tags::

    item.tags             what the ITEM says   — editable, direct
item.effective_tags   what the LIBRARY concludes — read-only

    The second is direct plus group-inherited plus implied, which is what search matches on. Writing to it would mean writing to a group or to an implication, which are different things in different places, so it is a frozenset and fails with the stdlib's own AttributeError.

    Tag ¶

    Tag(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    A row in the tag catalog.

    meta_tag_counts property ¶

    meta_tag_counts: dict[str, int]

    Pictures this tag has WHERE EACH META TAG SAYS — {"tumblr": 50, "twitter": 100}, nonzero entries only. The per-site successor of the old tag-level count_offset (one number could not say where it came from).

    Never added to a count the app displays — a total that silently included it would be the app making a claim about somewhere else. What it is FOR is ordering: the autocomplete's equal-count ties sort by the highest of these. (A training run could once balance against it, under the name the tag-level offset left behind; that freq_base value is gone.)

    set_meta_tag_count ¶

    set_meta_tag_count(name: str, count: int) -> None

    Set the count on one meta-tag assignment — assigning the meta tag first when the tag does not carry it yet. Logged and revertible like every other Tags-tab edit.

    alias_of property writable ¶

    alias_of: Optional['Tag']

    The tag this one is a second name FOR, if any.

    Assigning an alias redirects to its target, which is why an alias implies nothing of its own.

    namespace property ¶

    namespace: str

    The text before the first colon — costume in costume:tiger.

    implies property ¶

    implies: NameSet

    What assigning this tag also assigns, transitively.

    meta_tags property ¶

    meta_tags: NameSet

    What the TAG SET says about this tag — "noflip", "character" — in the same namespace links, captions and tag groups use.

    It never reaches a picture, so search, counts and training see no new tag; what reads it is what asks about the tag itself (TAG:noflip, and a training run refusing to mirror what carries it).

    items property ¶

    items

    Every item this tag is effectively on.

    item_count property ¶

    item_count: int

    How many items carry it, folded exactly as a search folds it.

    len(tag.items) is the same number for a tag whose name a search can be typed for, and this is the one to reach for when it may not be: items goes through the query grammar, which LOWERCASES what it is given, so a tag whose stored name carries a capital is not found by it at all — it answers 0 for a tag on a thousand pictures. The catalog's own names are case-preserving (an import can carry one), so this matches the name as stored.

    merge_into ¶

    merge_into(other, *, keep_alias: bool = True) -> 'Tag'

    Fold this tag into another and delete it. The old name lives on as an alias, so nothing still saying it goes looking for a tag that no longer exists.

    MetaTag ¶

    MetaTag(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    A name in the meta-tag namespace — the labels on links, captions and per-item tag groups. A separate namespace from item tags on purpose: these describe the annotation, not the picture, and never reach search.

    description property writable ¶

    description: str

    The long form, with line breaks — what a ? beside the name opens. comment is the one-liner that rides beside the name.

    delete ¶

    delete() -> None

    Remove it from every link, caption and tag group carrying it.

    Group ¶

    Group(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    A library group. Groups form a TREE — one parent at most.

    smart_query property writable ¶

    smart_query: str

    The SMART group's membership rule (the saved-search tag set); "" for an ordinary group too, since it has none. Smart is an IDENTITY fixed at creation (groups.create(smart_query=…)): assigning here edits a smart group's rule — refused on an ordinary group, and a smart group stays smart whatever the rule says (an empty rule holds nothing).

    path property ¶

    path: str

    Trips/2019/Japan — the names from the root down.

    items property ¶

    items

    Items directly in this group.

    tags property ¶

    tags: NameSet

    Tags this group GRANTS its items — inherited by the whole subtree.

    The highest-leverage write in the API: one assignment tags everything under it, and it is where most of a library's inherited tags come from.

    add ¶

    add(items) -> int

    Put items in this group (bulk — one call, one event each).

    duplicate ¶

    duplicate(parent=None) -> 'Group'

    A deep copy of this group and its subtree, sharing the items.

    delete ¶

    delete(*, assign_tags: bool = False) -> None

    Delete the group. assign_tags bakes what it granted onto its items first, so they keep the tags they were inheriting.

    FileSource ¶

    FileSource(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    Where a stored file's bytes came from: a filename with its import path, or a web URL with the time it was fetched.

    Artifact ¶

    Artifact(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    Something generated from a file and stored beside it — a depth map, a pose overlay, a cached training latent.

    stale property ¶

    stale: bool

    True when the source file was edited after this was generated.

    rel_path property ¶

    rel_path: str

    Where this sits inside the item's folder — the name File.artifact_name produces.

    parent property ¶

    parent: Optional['Artifact']

    The artifact this one was made FROM, when it was not made from the file itself — a latent cached off a degraded copy points at that copy, so deleting the copy takes its latents with it.

    File ¶

    File(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    One version of an item's bytes.

    number property ¶

    number: Optional[int]

    The stable per-item source number (#1, #2, …) — what names the file on disk.

    phash property ¶

    phash: Optional[str]

    The perceptual hash dedup compares. None for a video.

    rotation property ¶

    rotation: int

    Which way these bytes sit relative to the item's FIRST source file.

    Provenance, not a transform to apply: the pixels are already turned. width/height are likewise already in this orientation.

    crop property ¶

    crop: Rect

    This file's region of the item's reference frame.

    source_kind property ¶

    source_kind: str

    stored | video_frame | video_clip.

    frame_rate property ¶

    frame_rate: Optional[float]

    Frames per second, for a video. None when nothing probed it — which is a real state, not a zero: no ffprobe on the machine means a film imports with no duration and no rate at all.

    path property ¶

    path: Optional[Path]

    Where the bytes are on disk. None when the row has no stored file.

    This is the answer to "there is no export, but let me at the files".

    image ¶

    image()

    The pixels as a PIL image.

    The stored bytes are ALREADY in their final orientation — rotating an item writes a new file with the turned pixels — so rotation is provenance (which way these bytes sit relative to the item's first source file), not something to apply. Opening the path and rotating by it would turn every rotated picture twice.

    sources property ¶

    sources: HandleList

    Every recorded source of these bytes.

    add_source ¶

    add_source(name: str) -> FileSource

    Record a filename this file was seen under.

    add_url ¶

    add_url(url: str, *, accessed_at=None) -> FileSource

    Record a web address these bytes came from, and when.

    THE PROVENANCE CALL for an import: ImportResult.file names the stored file a source landed on — the EXISTING one for a duplicate, which is the case worth recording (one picture at a second address) — so got.file.add_url(url, accessed_at=fetched) is the line after every imported download. Idempotent per (url, access time): re-recording the same fetch answers the existing row, so a re-crawl needs no try/except; the same URL at a DIFFERENT time is a second, genuinely different record. An offset-aware time is stored as the UTC moment it names.

    artifact_name ¶

    artifact_name(kind: str, key: str = '', ext: str = 'bin') -> str

    The item-folder-relative name an artifact of this file WOULD have.

    Creates nothing and touches no disk. key is whatever makes one rendering different from another — a model, a size, a set of drawn parameters — and may be composed out of pieces; it is slugged, so which characters survive is not the caller's problem.

    artifact_path ¶

    artifact_path(kind: str, key: str = '', ext: str = 'bin') -> Path

    artifact_name as an absolute path — what you hand to a process that will write the bytes itself. The folder is created.

    find_artifact ¶

    find_artifact(kind: str, *, model: str = '', name: str = '') -> Optional['Artifact']

    The recorded artifact of this kind (and model, and stored name), or None. This is the cache lookup.

    Note it answers about the ROW. A row whose bytes have since been pruned still answers, which is why a cache that cares checks artifact.path too — the two can disagree, and re-encoding is cheaper than reading a file that is not there.

    add_artifact ¶

    add_artifact(kind: str, data: bytes, *, key: str = '', ext: str = '', model: str = '', width: int = 0, height: int = 0, parent: Optional['Artifact'] = None) -> 'Artifact'

    Store data at artifact_name(kind, key, ext) and record it.

    record_artifact ¶

    record_artifact(kind: str, *, key: str = '', ext: str = '', model: str = '', width: int = 0, height: int = 0, parent: Optional['Artifact'] = None) -> Optional['Artifact']

    Record bytes ALREADY on disk at artifact_path(kind, key, ext).

    For a file another process wrote — a trainer caching a tensor the library could not have produced. Returns None when nothing is there, and the existing handle when the row already exists, so running it again over a folder adds nothing.

    split_out ¶

    split_out() -> 'Item'

    Move this file into an item of its own, linked back to this one.

    For when the deduper grouped genuinely different pictures as versions of each other.

    delete ¶

    delete() -> None

    Remove this version, its bytes, its artifacts and its thumbnail.

    Caption ¶

    Caption(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    One caption on an item.

    tags property ¶

    tags: NameSet

    The caption's META tags — the app's own namespace, which never reaches a picture's tags, search or training.

    kind property ¶

    kind: str

    "caption" (what the picture is) or "instruction" (how it was made from the items in refs). Fixed when the row is created.

    refs property writable ¶

    refs: list

    An instruction's source images, IN ORDER. Empty for a caption.

    pending property ¶

    pending: bool

    True for a machine-written caption nobody has agreed to yet.

    approve ¶

    approve() -> None

    Agree with a machine's caption as it stands. Editing one approves it too; this is the button for when it needed no changing.

    Subject ¶

    Subject(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    Who or what a picture is OF — extra data on a tag.

    comment property writable ¶

    comment: str

    What tells two people of one name apart — the identity TAG's.

    since property writable ¶

    since: Optional[PartialDate]

    When they came into being — a birth date, a release date.

    tag property writable ¶

    tag: Optional[Tag]

    The tag this subject IS. None for a face cluster nobody has named.

    merge_into ¶

    merge_into(other, *, keep_alias: bool = True) -> 'Subject'

    Fold this identity into another: the faces move and the tags merge.

    delete ¶

    delete(*, with_tag: bool = False) -> None

    Delete the identity, keeping its tag — the pictures are still of something. with_tag deletes that too.

    Place ¶

    Place(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    Where a picture was taken — location data on a tag.

    name property writable ¶

    name: str

    What the place is called, as ONE line — an address, "the corner of the old market", "Bob's house". It was eight typed components with a per-country form; a place is a line somebody reads.

    parent property writable ¶

    parent: Optional['Place']

    The place this one is IN. Assigning it implies the parents — the containment is an ordinary tag implication under the hood.

    Event ¶

    Event(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    What was happening — a span of days on a tag.

    The MODEL is called Occasion, because Event is the modification log's row. The UI, the routes and this API all say "event"; only the ORM diverges, and this is where that stops mattering.

    comment property writable ¶

    comment: str

    The identity TAG's, like a subject's and a place's.

    span ¶

    span(start=None, end=None) -> None

    Set when it was. Either side may be None to leave it alone.

    places property ¶

    places: HandleSet

    Where it was. Every one must be NAMED — a venue is a tag on no item at all more often than not, and an unnamed place has no name for anything to refer to it by.

    Appearance ¶

    Appearance(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    One "this person is in this picture", optionally at one face.

    Several per item is the point: the same character twice on a page, at two ages. The AGE is a fact about the picture, not about the name on it.

    rect property writable ¶

    rect: Optional[Rect]

    The appearance's SUBJECT BOX — the whole figure, where the face is only the head. None until somebody draws one.

    points property writable ¶

    points: Optional[list]

    The subject box's optional polygon (Box.points' rule: while one is set, rect is its bounding box).

    guessed property ¶

    guessed: bool

    A machine said this and nobody has agreed yet.

    confirm ¶

    confirm() -> None

    Agree with a guess. Its pending tag stops being pending, which is what lets search, training and export see it at last.

    Face ¶

    Face(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    A crop a detector found, or a hand drew.

    Evidence, not an edit: it keeps its box, its score and its descriptor forever, named or not, and a re-run never loses work.

    outline property ¶

    outline: Optional[Rect]

    The face's optional OUTLINE — the whole figure, drawn by hand, where the face box is only the head. A subject attached to the face uses it wherever it has no subject box of its own.

    outline_points property ¶

    outline_points: Optional[list]

    The outline's polygon (Box.points' rule: outline is then its bounding box).

    det_score property ¶

    det_score: Optional[float]

    How sure the detector was. None for a face somebody drew.

    models property ¶

    models: tuple[str, ...]

    Every detector that found this face — one head, one rectangle, so several models may agree on it.

    appearances property ¶

    appearances: tuple[Appearance, ...]

    Every claim on this face — who, how sure, and how old they are in it. A face may be several people at once, so this is a tuple.

    subjects property ¶

    subjects: tuple[Subject, ...]

    Just the people, which is what the name promises.

    This used to return the Appearance rows, so face.subjects[0] .display_name — the obvious line — raised. Item already had the pair, and Face disagreeing with it was one word doing two jobs.

    name ¶

    name(who, *, comment: str = '') -> 'Face'

    Say who this is — ADDING a claim, not replacing one.

    A face may be several people at once (a drawn character and the actor who plays them), so this appends. unname takes one off, and is remembered differently: taking off a machine's GUESS records a refusal so the next run does not offer it again.

    crop ¶

    crop(*, margin: float = 0.25)

    The face as a PIL image, cut out of its item's picture.

    TextRegion ¶

    TextRegion(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    A region of text an OCR engine read, or a hand drew.

    Evidence, not an edit, like a :class:Face — a re-run refreshes where it is and never what a person said it says. Regions form a tree (a block holds lines, a line holds words), as deep as the engine actually went.

    level property ¶

    level: str

    "block" | "line" | "word" | "char".

    order property ¶

    order: int

    Reading order among siblings — the engine's own.

    quad property ¶

    quad: tuple[tuple[float, float], ...]

    The engine's own four points for a rotated shape; empty when the rectangle IS the shape.

    score property ¶

    score: Optional[float]

    The engine's confidence. None when it has none to give (Magi is generative) — whether a region is hand-drawn is models, not this.

    models property ¶

    models: tuple[str, ...]

    Every engine that read this region — empty for one drawn by hand.

    edited property ¶

    edited: bool

    Whether a person corrected the text. After that, no run rewrites it — set by assigning text, never directly.

    children property ¶

    children: HandleList

    The finer regions inside this one (a block's lines, a line's words), in reading order.

    crop ¶

    crop(*, margin: float = 0.05)

    The region as a PIL image, cut out of its item's picture. The default margin is text's own — glyphs unshaved, not head and shoulders.

    delete ¶

    delete() -> None

    Remove the region and everything under it. Prefer dismissing a detected false positive — a deleted one comes back on the next run.

    Link ¶

    Link(lib, row_id: int, row=None, *, outgoing: bool = True)

    Bases: Handle

    A directed edge between two items — an edit to what it came from, a panel to its page, a still to its film.

    flip ¶

    flip() -> 'Link'

    Reverse which end is the original. For an edit link this re-roots the whole cluster, so "one original per item" stays true.

    Sequence ¶

    Sequence(lib, row_id: int, row: Optional[T] = None)

    Bases: Handle

    An ordered run of items — a chapter, a film's frames, a set.

    kind property ¶

    kind: str

    How it came to be: archive | pdf | gif | manual (an older library may hold video, from a removed import option). Provenance only — all sequences behave alike, but a re-import recognises its own by it.

    item property ¶

    item: Optional['Item']

    The CONTAINER item, so a sequence can be selected and tagged like anything else in the grid.

    members property ¶

    members: HandleList

    The items, one entry per POSITION — a book's repeated blank page is one item listed at each of its positions. This list speaks in ITEMS: deleting one removes every occurrence, and reorder refuses a sequence that repeats an item (a list of items cannot say which copy goes where — the app's own reorder addresses membership rows).

    remove ¶

    remove(items) -> int

    Take items out — EVERY occurrence of each; that is what "remove this picture from the chapter" means.

    delete ¶

    delete() -> None

    Remove the sequence and its container, keeping the members.

    TagSet ¶

    TagSet(item: 'Item', negative: bool = False)

    Bases: NameSet

    An item's DIRECT positive tags, with .negative beside it.
