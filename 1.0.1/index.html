    Compost, for media

    A local web app that turns a pile of images and videos into datasets: import without duplicates, tag and caption at scale, search and organize, and train a model on the result — or read the library from your own Python scripts.

    Install

    Python 3.11 or newer — or Docker, which needs not even that. A release wheel carries the built web app inside it, so there is nothing to compile and no Node on your machine (building it yourself wants Node 20.19 or newer).

    Full installation guide → 
    python3 -m venv ~/media-compost
~/media-compost/bin/pip install "media-compost[full]"
~/media-compost/bin/media-compost serve

    Videos need ffmpeg for probing and frame extraction:

    brew install ffmpeg
    python3 -m venv ~/media-compost
~/media-compost/bin/pip install "media-compost[full]"
~/media-compost/bin/media-compost serve

    Videos need ffmpeg for probing and frame extraction:

    sudo apt install ffmpeg        # or your distribution's equivalent
    py -3.11 -m venv %USERPROFILE%\media-compost
%USERPROFILE%\media-compost\Scripts\pip install "media-compost[full]"
%USERPROFILE%\media-compost\Scripts\media-compost serve

    Videos need ffmpeg on your PATH:

    winget install Gyan.FFmpeg
    git clone https://github.com/mediacompost/media-compost
cd media-compost
python3 -m venv .venv && .venv/bin/pip install -e ".[full]"
./scripts/build.sh
.venv/bin/media-compost serve

    Building the web app yourself needs Node 20.19+ (or 22.12+).

    node --version
    git clone https://github.com/mediacompost/media-compost
cd media-compost
docker compose up -d          # http://localhost:8000

    The image builds the web app itself; ffmpeg is already inside.

    docker compose logs -f

    serve starts on 127.0.0.1:8000 (--open also opens your browser on it). The library lives in a folder you can back up, move between machines, and read without this app.

    What it does

    A library for pictures and film that knows what is in them — what you already have, what each thing is, who is in it and where it was taken — and does enough of the work for you that saying so is possible at all across forty thousand pictures. Every card here links the page that explains it.

    Everything in one library

    Images, videos, animated GIFs, PDFs and comic archives, dragged into the window or imported from the command line. A GIF's frames and a PDF's pages arrive as the ordered pages of one item rather than as a heap of files.

    Importing files →

    Nothing lands twice

    Every file is checked against the whole library by its content and by how it looks, so an exact copy is adopted and a rescale becomes another version of the picture you already have. Your folder structure becomes groups, the original filenames are kept, and a screenshot is matched to the film it came from and linked at its timestamp.

    Importing files →

    Order that matters

    A sequence keeps items in order — a comic's pages, an animation's frames, a burst of photos. It is an item in its own right, so it can be tagged, grouped and searched like any other.

    Browsing the library →

    Groups, however you like

    An item can be in as many groups as you want, groups nest, and each has its own colour and icon. A smart group is a saved search instead: whatever matches is in it, kept up to date by itself.

    Browsing the library →

    Press space

    The picture you have selected, full size over a dimmed library — or the video, playing. The arrow keys step through what you picked and through a book's pages, the wheel zooms, and one key puts the item's tags and captions beside it.

    Quick Look →

    Every change, and the way back

    Everything you do is written to a log you can read: what changed, when, and by whom. Almost all of it reverts — one entry, a whole run of them, or straight from an undo bar where you made the change.

    History →

    Search that reaches everything

    A search bar and a visual builder that are the same query bound both ways: type it, or click it together. It reaches tags, people, places, capture dates, captions, links — and every metadata field the files themselves carry, down to the camera and the ISO.

    Searching →

    Tags that mean something

    Tags imply other tags, so a search for dog finds the poodles without anybody tagging both. They carry other spellings as aliases, merge without losing an assignment, live in namespaces like costume:hat, group per picture, and can hold a number to compare against (height:172cm).

    Tags →

    Who, where and when

    A person, a place or an event is extra data on a tag, so naming somebody is tagging the picture — nothing new to search. Places sit inside one another, events span days and name their venues, and an event can say when an undated picture was taken.

    Subjects and faces → Places → Events →

    A tag scheme you already use

    Import one — a booru list, your studio's own — and it describes names wherever you type a tag: autocomplete, a line saying what each one means, and the longer version behind a mark. Nothing is written into your library until you actually assign a tag.

    Tag sets →

    Labels on the labels

    A meta tag marks a tag, a caption or a link rather than a picture — “never mirror this one”, “this caption is a draft”. Then a search can ask about what things are marked instead of listing them one by one.

    Meta tags →

    Captions, and instructions

    A caption says what a picture is. An instruction says how it was made from other pictures, and links them in the order they were used — which is what an image-editing model trains on.

    The item panel →

    Models that run on your machine

    Generate tags and captions, read the text off a page, remove a watermark, upscale, colorize, cut a comic into its panels, find faces. Each model downloads its own weights and runs in a process of its own — no account, no API key, and nothing leaves the machine.

    Settings and models →

    Tag a pile of pictures fast

    Sessions that put one question in front of you at a time and sort the queue by likeness, so the pictures that fit a tag arrive together. A grid of sixteen, pre-sorted into fits / doesn't fit / undecided, is the quickest way through a folder nobody has tagged.

    Tagging sessions →

    Rate a few, sort the rest

    Rate pictures by comparing two at a time, and the standings are worked out from your answers. Then spend them on the rest of the library: it learns what you rated highly and writes the tags you ask for wherever a picture lands.

    Rankings →

    Draw on it

    Draw a box by dragging, or a polygon corner by corner; on a film a tag is a stretch of time instead. Faces and text are found for you — two face detectors, one of them for drawn art, and two text engines — and everything a model suggests waits for your nod.

    Annotation editor →

    Edit the pixels

    A raster editor with selections, brushes, transforms and an inpainting tool that paints a region away. For film, a cutlist: trim, split, move, rotate, crop, change the frame rate — and nothing touches the file until you save.

    Image editor → Video editor →

    Train on your own library

    Point a LoRA, a LoKr or a full finetune at a search of your library and queue it. Watch the loss and the sample images as they land, keep any checkpoint, and generate test pictures without leaving the app — the weights are written in the layout ComfyUI and the rest read.

    Training → Evaluate →

    Get your files in

    Drag files or folders anywhere into the window — or, faster for large datasets, import from the command line. Archives are unpacked, duplicates are detected against the whole library, and folder structure can become groups. Re-importing the same files is safe.

    Command line
    # bulk-import a folder — its structure becomes nested groups
$ media-compost import ~/Pictures/dataset --data-dir ./lib --parent-group Scans
    Python
    # one run: one commit rhythm, one History entry, a URL recorded per file
from media_compost import ImportBytes, open_library

with open_library("/path/to/library", user="scraper") as lib:
    with lib.importing() as run:
        for data, url, when, name in downloads():
            got = run.add(ImportBytes(data=data, name=name))
            if got.file:
                got.file.add_url(url, accessed_at=when)
            if got.item:
                got.item.tags.add("scraped")
    Importing files → Command line →

    Then say what they are

    Everything the interface writes, a script writes the same way — through the same service layer, so a tag, a box, a caption or a date lands in the History log as its own entry and comes back out of it. One picture, or everything a search matches, in one transaction.

    One item
    from media_compost import open_library

with open_library("/path/to/library", user="my-script") as lib:
    item = lib.items["9f3c…"]                    # by uid, or by id
    item.tags.add("temple", box=(0.31, 0.12, 0.40, 0.55))
    item.tags.negative.add("blurry")             # pointedly NOT blurry
    item.groups.add(lib.groups["Trips/2019/Japan"])
    item.add_caption("A five-storey pagoda in the rain.")
    item.taken = "2019-04"                        # a month is a date too
    Or a whole search — logged, and revertible
    with open_library("/path/to/library", user="my-script") as lib:
    mark = lib.history[0].id             # note where the log stands

    small = lib.query("INFO:width<800 !lowres")
    small.add_tags("lowres")              # one transaction, not one per item
    small.add_to(lib.groups["Needs work"])

    lib.history.revert(lib.history.since(mark))       # …if that was a mistake

    And back out again

    There is no export step. The library is a Python package as well as a web app, so a script reads everything the interface shows — what a picture is tagged, who is in it, what its own file says about itself — and asks an item where its bytes are instead of writing a copy of them somewhere. Queries take the same string the search bar takes.

    What the library knows
    # mode="r" refuses every write before touching the database
with open_library("/path/to/library", mode="r") as lib:
    for item in lib.query("portrait TAKEN:@2019").prefetch("tags", "subjects"):
        meta = item.metadata                  # intrinsics, EXIF, IPTC, pins
        print(item.uid, item.width, item.height,
              meta.get("camera_model"), meta.get("iso"), meta.get("location"),
              item.taken_effective,           # typed, else EXIF, else its events
              [who.display_name for who in item.subjects],
              sorted(item.effective_tags))    # direct + inherited + implied
    Where the files are
    with open_library("/path/to/library", mode="r") as lib:
    for item in lib.query("scan INFO:width>=3000", kind="image"):
        print(item.path)                  # the bytes where they lie — no copy
        item.image().convert("L").save(out / f"{item.uid}.png")

    # a film hands over its frames without storing any of them
    for index, seconds, frame in lib.items["9f3c…"].frames(fps=1.0, max_dim=1024):
        frame.save(out / f"{index:05d}.png")

    And when it's time to train

    Everything above is what a training run reads — the tags with their boxes, the captions, the people — whether the trainer is the built-in one or your own script reading the library through the Python API.

    In the app

    The Train tab queues LoRA, LoKr or full-finetune runs against a search of the library — SD 1.5, SDXL, FLUX, Chroma, Qwen-Image, Z-Image and your own weights — with the memory a run will need worked out as you edit it. Watch the loss and sample images live, pause and resume across restarts, and keep any checkpoint: the weights are written in the layout other tools load. The Evaluate tab generates test images from any checkpoint without leaving the app — and on a machine that will never train, one switch removes all of it.

    Training →
    In your own pipeline
    # images beside .txt caption files — the layout most trainers read
with open_library("/path/to/library", mode="r") as lib:
    q = lib.query("portrait !lowres INFO:resolution>=1.0", kind="image")
    for item in q.prefetch("tags", "files"):
        dest = out / f"{item.uid}{item.path.suffix}"
        shutil.copy2(item.path, dest)
        dest.with_suffix(".txt").write_text(", ".join(sorted(item.effective_tags)))
